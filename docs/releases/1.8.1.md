# Pulse 1.8.1 — steadier search times, smaller cache, more reliable ranking

## Fixes and changes
- **Cross-encoder stall fixed.** Background pre-scoring took the ranking lock and then waited for it again, so it never scored anything and could block the final ranking for up to 12 seconds. This caused occasional very slow searches in 1.7.12–1.8.0.
- **Background work targets the right papers.** While sources are still answering, Pulse now embeds and pre-scores exactly the papers the final ranking will assess, refreshed as each citation source finishes. Background work only fills caches; the final ranking is computed once from the full pool and is unchanged (covered by an equivalence test).
- **Persistent ranker protocol.** The cross-encoder can run as a long-lived worker (JSON lines with request ids, timeouts on every platform, restart on failure, warm-up at launch). The offline ranker bundled in this DMG is the same one shipped with 1.8.0, which predates the protocol, so it runs in single-shot mode; persistence applies to rankers built with the updated build script.
- **Citations: OpenAlex first.** Semantic Scholar is used only when OpenAlex has nothing and is not rate-limited; OpenCitations is a keyless fallback. Seed papers are resolved once, in parallel.
- **Two-phase results.** The text-and-citation order appears while AI ranking finishes. If you have started marking papers, your order is kept and **Apply refined order** is offered instead.
- **Pre-warm on selection** starts after a paper stays selected for 1.5 seconds and is cancelled when a search starts.
- **Smaller cache.** Cached responses are compressed; five searches now use about 18 MB instead of 107 MB, and the cap is 1 GB.
- **Allow helper fixed.** `Allow-Pulse-Tauri.command` now accepts the version it ships with (it previously required 1.3.1).

## Measured (five seed papers, 200 results, Apple Silicon Mac, fresh profile, one run each, run back to back with 1.8.0)

| | 1.8.0 | 1.8.1 |
| --- | --- | --- |
| Cold search, median (max) | 11.5 s (22.8 s) | 11.5 s (12.7 s) |
| Ranking stage after collection | 4.3–14.2 s | 2.7–6.2 s |
| Search after selection pre-warm, median | — | 8.8 s |
| Repeat search, median (max) | 2.5 s (10.9 s) | 2.9 s (6.6 s) |
| Must-find papers in top 20 / 50 / 200 (of 75) | 14 / 21 / 53 | 13 / 21 / 54 |
| HTTP cache after five searches | 107 MB | 18 MB |

Collection from public services (5–7.5 s) now dominates cold time, so the median did not fall; the 8-second cold target was not met. The must-find set rewards citation links and is partly circular with the citation bonus; quality differences of one paper are within run-to-run noise.

The Apple Silicon package keeps its macOS 11+ target, PDF support and self-contained offline cross-encoder. The main backend requires Python 3.10+. The app is ad hoc signed and not Apple-notarized.
