# Pulse 1.7.10 — DBEF discovery and in-text citation lookup

The supplied content-aware DBEF scorer is built into Pulse. It replaces the legacy co-citation network pass and the bibliographic search that used only the first four seed references. The **DBEF** search control finds shared-reference neighbours using pivots weighted by specificity and title/abstract relevance, then ranks them with bibliography-length saturation, content similarity and recent citation velocity.

- Direct citations, semantic recommendations, searches across selected literature indexes and optional full-text retrieval remain complementary. Equivalent provider query strings execute once, and concurrent identical cached metadata GETs share their network request.
- DBEF uses sparse standard-library TF-IDF rather than adding NumPy/scikit-learn or another model download to the app. The supplied scoring equations, tokenizer and content floors are retained. Missing reference counts are neutralized with the observed median for internal weighting; reported unknown citation counts remain unknown.
- Collection is capped at 12 seconds, respects shorter parent budgets and preserves collected results. Metadata lookups are batched, and weighted pivots are balanced across seeds. DBEF contributes one retrieval channel, avoiding duplicate votes from multiple reference pivots, and its candidates receive no second generic citation-velocity bonus.
- Results explain their shared references, supply weighted evidence for multi-seed bridges and retain DBEF provenance when added to the library. The old `citationNetwork` API/workspace key remains compatible. Citation-depth controls apply only when direct citation discovery is enabled.

Paste an author–year citation into **Add paper** to search Crossref and OpenAlex for possible papers and their indexed DOIs. The picker checks first-author surname and publication year, supports accented/compound surnames, named coauthors, grouped citations and year suffixes, and requires selecting a title before adding it. Optional title words narrow the online search. Ambiguous or failed lookups preserve the library without importing placeholders.

The previous 200-result default is removed. New and migrated 200-result workspaces default to 500, with choices up to 1,000 and 2,000. Europe PMC uses cursor pagination with at most 1,000 records per request; Semantic Scholar's single-response recommendations and citation calls retain their supported 500-record cap. Search text pagination and combined results can exceed 500. Collection deadlines and neural shortlists remain unchanged, so requesting 2,000 does not guarantee a provider finds that many within its budget.

See the [implementation guide](../search/DBEF.md) for the equations, assumptions and limits. Six synthetic comparisons with the supplied NumPy scorer returned identical top-20 lists, with a maximum score difference of about `3.6e-15`. A live check on a public open-access research paper collected 131 candidates and returned 20 DBEF-ranked results in one sample of about 8.2 seconds. These checks validate integration and scoring math, not general retrieval quality or latency.

The Apple Silicon package retains its macOS 11+ target and self-contained offline cross-encoder. The main backend still needs Python 3.10+; Ollama and optional local embedding/report models remain separate. No personal library, credentials or new runtime dependencies are packaged. The app is ad hoc signed and is not Apple-notarized. The linked published Windows installer remains 1.7.6; current Windows source continues to build in CI.
