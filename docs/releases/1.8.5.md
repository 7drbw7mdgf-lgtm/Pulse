# Pulse 1.8.5 — Mendeley sign-in and library sync fixed

## Mendeley
- **Sign-in works again.** Mendeley's servers rejected every request Pulse made, including the sign-in step, because Pulse used Python's default identification. That produced "Could not finish Mendeley sign-in". Pulse now identifies itself, and if sign-in still fails the message gives Mendeley's reason.
- **Library sync works end to end.** Pulse now uses the profile and document formats Mendeley currently requires and follows its page links to the end of the library. On a 347-record library, every record was read; the 329 distinct papers were imported and the 18 duplicate copies inside Mendeley were merged.
- **Repeat syncs are quiet and safe.** A sync now applies only what changed in Mendeley since the last sync. Pulse's own metadata corrections (for example a repaired DOI or title capitalisation) are no longer reported as "local edits" every time, and duplicate copies in Mendeley no longer re-link papers or create extra copies. Your edits still win when both sides changed the same field.
- **Connection settings are visible.** If you use your own Mendeley application, enter its client ID, secret and redirect URL under **Settings → Mendeley & Zotero** or **Connection settings** in the Library connections dialog.

## Map
- Fixed a crash in the topic-cluster view when the library contained papers that are not on the active map (for example right after a large import).

Not tested live: sending papers *to* Mendeley (it would write to a real account); its request format is unchanged apart from the new identification. The Windows installer remains 1.8.0. The app is ad hoc signed and not Apple-notarized.
