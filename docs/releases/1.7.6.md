# Pulse 1.7.6

12 October 2026

## Discovery & Embedding Performance

- **Embed while collecting:** Candidate papers arriving from network branches (OpenAlex, Semantic Scholar, Europe PMC, CORE) are dispatched to a concurrent background embedding worker as partial batches stream in. Seed papers and research questions are embedded immediately, overlapping neural embedding computation with network wait time and saving ~25 seconds per search.
- **Pre-filtered semantic embedding pool:** All candidate papers are scored cheaply first using BM25 text relevance and reciprocal rank fusion (RRF) citation evidence. Only the top ~250 candidates are submitted to the neural reranker instead of 600–1200, cutting embedding runtime by an additional ~10 seconds without sacrificing discovery accuracy.
- **Persistent SQLite embeddings on disk:** Local embeddings are now persisted to SQLite (`embedding-cache.sqlite3`) keyed by endpoint, model, and DOI/text hash. Repeat searches, query adjustments, and papers shared across seeds load instantly across app restarts.
- **Fast embedding mode (`all-minilm`):** Added an optional "Fast embedding (all-minilm)" mode toggleable in the search configuration ribbon. When enabled, Pulse prioritizes `all-minilm`, providing ~3.7× faster embedding throughput for fast exploration.

## Retrieval Resilience & Service Error Handling

- **Semantic Scholar 403 recovery:** If an invalid or restricted Semantic Scholar API key returns HTTP 403 Forbidden, Pulse marks the key invalid for the session and immediately retries the request unauthenticated, preventing search failures.
- **Skip failing services on HTTP 500 / unavailable:** When an external search provider returns HTTP 500, 502, 503, 504, or access errors (such as upstream CORE service outages), the query planner immediately terminates further queries for that provider rather than repeatedly retrying across all 26 planned queries.
- **Batched, sorted OpenAlex reference lookups:** Reference lookups query `filter=cited_by:{seed}` sorted by citation count descending with `per-page=200`, retrieving landmark foundational references in a single request. Fallback references batch up to 100 IDs per chunk.
- **Increased OpenAlex concurrency:** Relaxed host rate limiting for `api.openalex.org` to allow up to 10 concurrent requests, maximizing throughput within OpenAlex's 10 req/s threshold.

## Paper Access & Native Links

- **Multi-source paper open resolution:** Enhanced `paperOpenUrl` to generate valid direct URLs across DOI, OpenAlex (`openAlexUrl`/`openAlexId`), Semantic Scholar (`s2PaperId`), PubMed (`pmid`), PMC (`pmcid`), Europe PMC (`europePmcId`), and arXiv (`arxivId`).
- **Full-text links:** Exposed direct full-text and PDF links alongside primary article links in the paper preview card.
